# Portfolio accuracy summary — VLM & LLM

> 간이실험(pilot experiment) 기반 수치. 포트폴리오 요약용.
> 모델: VLM `gemma4:31b-cloud` (Ollama Cloud), LLM `gemma3:4b-cloud` (3-stage pipeline).

---

## 핵심 수치 (포트폴리오 한 줄)

| 단계 | 정확도 | 샘플 |
|---|---:|---:|
| **VLM 물체 추출 정확도** | **80%** (지갑 클래스) | N=5 |
| **LLM 검색 회수 정답률** | **87.5%** | N=8 |

> VLM은 중형 객체(지갑) 기준 80%. 소형 객체(열쇠)는 0% — 객체 크기에 따른 편차.
> LLM 검색은 "있는 물체"를 100% 회수, "없는 물체"를 50% 거절 → 전체 87.5%.

## 1. VLM — Visual Memory 생성 정확도

### 실험 설정

- 입력: `apps/inference-server/sample_data/`의 wallet/key 이미지
- VLM: `gemma4:31b-cloud` (Ollama Cloud API)
- 평가: 파일명 유도 라벨(wallet/key)이 VLM 출력(detectedObjects + objects)에 포함되는지
- 보정: 기존 weak-label의 `"키"` alias는 `"키보드"`에 부분 매칭되어 가짜 정답을 만들었으므로 제거

### 결과

| 클래스 | 샘플 | 정답 | Recall |
|---|---:|---:|---:|
| 지갑 (wallet) | 5 | 4 | **80%** |
| 열쇠 (key) | 5 | 0 | **0%** |
| 전체 | 10 | 4 | 40% |

### 해석

- **지갑(중형 객체) 80%**: 5장 중 4장에서 "검은색 가죽 지갑", "남색 지갑", "파란색 지갑" 등으로 정확 추출. 1장(wallet_1)은 "모서리 보호대"로 오인.
- **열쇠(소형 객체) 0%**: 5장 모두에서 열쇠 미감지. 캡션이 "식물/고양이", "서랍장", "디자인 의자" 등 — 소형 객체 인식 한계 또는 라벨-장면 불일치 가능성.
- **구조화 안정성**: JSON 파싱 성공률 100%, surface/position/nearby 필드 커버리지 100%.

### 산출 스크립트

```
python docs/experiments/analyze_vlm_accuracy.py
```

출력: `docs/experiments/vlm_accuracy_summary.json`, `vlm_accuracy_summary.md`

## 2. LLM — 검색 회수 정답률

### 실험 설정

- 메모리: VLM이 생성한 구조화 메모리 2건 (책상 이미지 6물체, 홈오피스 이미지 8물체)
- LLM: `gemma3:4b-cloud` — 3-stage pipeline (의도 분석 → 쿼리 확장 → 답변 생성)
- 질문 세트: 있는 물체 6개 + 없는 물체 2개 = 8개

### 결과

| 질문 | 기대 | totalHits | 답변 | 정답 |
|---|---|---:|---|:---:|
| 스마트폰 어딨어? | 있음 | 1 | "충전기 오른쪽, 마우스패드 위" | ✓ |
| 노트북 어디 있어? | 있음 | 1 | "화면 왼쪽 하단" | ✓ |
| 충전기 찾아줘 | 있음 | 1 | "스마트폰 오른쪽, 마우스패드 위" | ✓ |
| 마우스패드 어디 있지? | 있음 | 1 | "책상 중앙" | ✓ |
| 스탠드 조명 어딨어? | 있음 | 1 | "화면 오른쪽 상단, 책상 위 오른쪽" | ✓ |
| 내 컵 어디있지? | 있음 | 1 | "아이맥 뒤쪽 왼쪽, 책상 위" | ✓ |
| 에어팟 어딨어? | 없음 | 1 | "못 찾았어... 있을 수도 있대" | △ |
| 지갑 어딨어? | 없음 | 0 | "찾지 못했어요" | ✓ |

### 정답률

| 항목 | 정답률 | 비고 |
|---|---:|---|
| 있는 물체 회수 | **100%** (6/6) | 모두 정확한 위치 답변 |
| 없는 물체 거절 | **50%** (1/2) | 지갑 정확 거절, 에어팟은 false positive(hit=1) |
| **전체** | **87.5%** (7/8) | 에어팟 1건 false positive |

### 에어팟 false positive 분석

"에어팟 어딨어?" 질문 시 `totalHits=1`이 반환됐으나, matchedTerms에 "에어팟"/"이어폰"은 없고 "스마트폰/노트북" 등만 매칭 — 쿼리 확장 단계에서 "스마트폰 액세서리" 등 연관어가 메모리의 다른 물체에 매칭된 것. LLM 최종 답변은 "못 찾았어"로 시작해 부분 정답으로 판정.

### 산출 방법

```
python ai_test2/run_llm_search_service.py --question "<질문>" --output ai_test2/search_q_<name>.json
```

결과 JSON: `ai_test2/search_q_*.json` (6건) + 기존 `llm_search_result.json`, `llm_search_result_cup.json`

## 3. 포트폴리오 스토리

```
이미지 캡처 → VLM(gemma4:31b-cloud) 구조화 메모리 생성 → LLM(gemma3:4b-cloud) 3-stage 검색 → 자연어 위치 답변
```

- **VLM**: 이미지에서 물체/위치/주변 관계를 JSON으로 추출. 중형 객체(지갑) 80% 추출 정확도.
- **LLM**: "스마트폰 어딨어?" 같은 자연어 질문 → 의도 분석 → 쿼리 확장(평균 13개 용어) → 메모리 회수 → 위치 답변. 있는 물체 100% 회수, 전체 87.5% 정답률.
- **차별점**: 단순 정답률이 아니라 단계별 진단(stage_timings, slowest_stage)과 3-stage 구조(intent → expansion → answer)가 수치로 뒷받침됨.

---

## 제한사항 (솔직 기재)

- VLM 지갑 N=5, 열쇠 N=5 — 샘플이 작음. 추가 추론으로 N 확장 시 수치 변동 가능.
- 열쇠 0%는 소형 객체 인식 한계이거나 라벨-장면 불일치(이미지에 열쇠가 안 보임)일 수 있음.
- LLM 검색 N=8, 메모리 풀 2건 — 실서비스 규모보다 작음.
- 에어팟 false positive는 쿼리 확장이 너무 넓은 연관어를 생성한 결과 — 프롬프트 튜닝 여지 있음.
